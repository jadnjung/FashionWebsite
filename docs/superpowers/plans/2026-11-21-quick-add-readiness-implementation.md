# Quick Add Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Keep one frontend owner for these overlapping components; root coordinates independent reviews, integration and publication.

**Goal:** Make Quick Add truthfully unavailable before hydration, then open a usable native frame immediately while its deferred shopping body loads or recovers.

**Architecture:** Keep the existing native frame, controlled Escape and close-notification counter in a lightweight QuickAddPanel. Import that frame synchronously from QuickAddTrigger and extract shopping responsibilities to a single deferred QuickAddBody. Native modality owns background interaction; local code-attempt identity/deadline owns asynchronous body readiness.

**Tech Stack:** Installed Next.js 16.3.1, React/React DOM 19.2.8, TypeScript, Tailwind 4, Playwright 1.62.1 and Vitest node environment. No new dependencies.

**Spec:** [Quick Add readiness design](2026-11-21-quick-add-readiness-design.md). Read both documents; root selected B subject to the integration and bundle gates.

## Global Constraints

- Preserve D-071's heavy-code splitting, hover/focus preload and persistent dialog lifetime; controlled Escape and close-notification accounting; native focus restoration; fresh selections and per-opening request ownership; and accepted-intent analytics.
- No new dependencies, eager shopping body, automatic retries/reloads, runtime-internal calls or unrelated refactors.
- Do not put the frame behind a transition, Suspense fallback or another chunk.
- Use a 10,000ms code-attempt budget from open-frame acquisition/Retry; keep the product request's separate 10,000ms budget.
- One accepted ready activation emits quick_add_open once; code Retry recovers that intent without another event. A fresh activation after closing is a new intent.
- Copy: QUICK ADD; CLOSE; Loading Quick Add…; Quick Add could not load.; Retry; VIEW PRODUCT. Initial accessible description: Quick Add is loading. View this piece to choose options.
- Root owns other project documents and the commit; preserve other edits, debug.log and Claude compatibility files. Publication only to surfacebook, with branch verified separately before commit and push and explicit destination refs/heads/surfacebook.

## Review Focus

1. Hover/focus preload rejects before any activation: no unhandled rejection, false intent or page-level error; the next accepted activation can recover (Task 2).
2. A code promise resolves after Close, timeout, replacement or unmount: it may warm cache but cannot mount obsolete body work or steal focus (Task 2).
3. Shared acquisition is still pending when Retry begins: only the newest bounded attempt may publish readiness/error; completion after timeout without Retry stays closed to body work (Task 2).
4. Two different cards are activated while body code is held: the urgent native modal blocks the second normal action, so no stacked stale dialogs or extra intent (Task 2).
5. Shared shopping helpers already occur in another initial route bundle: attribute the actual eager-frame delta and body-specific code, without claiming all shared bytes are newly eager/deferred (Task 3).
